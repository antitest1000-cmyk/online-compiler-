Fix: fatal error: conio.h: No such file or directory

Why modern compilers reject your college C assignments and how to easily fix the code.

Why does this error happen?

If you are copying C code from an old textbook or a college manual, you might see this error when running it in an online compiler or a modern desktop compiler (like GCC or Clang): 

fatal error: conio.h: No such file or directory

The <conio.h> header (Console Input/Output) is a DOS-specific header file created by MS-DOS compilers like Turbo C. It is not part of the standard C library. Therefore, modern cross-platform compilers do not include it.

How to fix the error

The fix is extremely simple: you just need to remove the DOS-specific functions and the header inclusion from your code. Here are the three steps:

1. Remove the include statement

Delete or comment out the line at the top of your file:

// #include <conio.h>

2. Remove clrscr()

clrscr() was used to clear the DOS screen before printing new output. Modern IDEs and online compilers handle the screen automatically. Just remove the clrscr(); line from your code.

3. Remove or replace getch()

In Turbo C, getch() was often placed at the very end of main() to pause the screen so you could read the output before the window closed. Modern IDEs and terminal windows stay open after execution finishes, making getch() completely unnecessary for this purpose. Just delete it!

If you genuinely need to read a single character of input for your program logic, you can use the standard C function getchar() from <stdio.h> instead.

Now that you've removed the old Turbo C functions, your code is 100% standard C! You can run it right here in your browser.
